# macOS 1.1.3 setup readiness and retry correction

Local review only, 5 October 2026. Version/build remains **1.1.3/3**. This correction preserves the completed allowance, native update, setup guide, artwork and notch work. Concurrent setup-copy/demo edits are left outside this commit and its isolated build snapshot. Windows and per-project work remain parked.

## Behavior

- Check Setup separates freshly verified sign-in from allowance availability. Missing allowances and unsupported formats no longer imply failed authentication. Verified retrieval failures retain sign-in readiness while monitoring reports unavailable or stale. Logout, account changes, failed verification and disablement clear readiness.
- Known API/external billing modes show a detected mode with unsupported monitoring; no assertion is made that those credentials were validated.
- Explicit Retry can recheck installation/sign-in during generic exponential error cooldown. Real user attempts have a ten-second per-provider minimum, coalesce active queries and never bypass an unexpired provider rate-limit embargo. Toggles, activity and wake respect that minimum. Waiting/countdown text distinguishes generic automatic retry, click cooldown and rate limiting. No extra automatic query follows an ordinary successful manual check.
- Codex client metadata now uses the validated bundle marketing version, with a deliberate 1.1.3 fallback for hostless contexts. Client name, app build, provider collection and authentication behavior are unchanged.
- Diagnostics retain only fixed categories. They exclude bindings, raw responses, provider messages and retry timestamps.

## Validation

The isolated Debug suite ran 198 tests: **196 passed, two skipped, zero failed**. The skipped tests were separate opt-in live-provider and allowance-render checks. A subsequent targeted read-only live-provider check passed on this Mac: both account bindings were verified, Codex returned a weekly window and Claude returned five-hour plus weekly windows. That evidence does not verify other accounts, plans or billing modes; missing/unsupported/retrieval/retry scenarios use synthetic fixtures.

New regressions cover authentication versus monitoring states, invalid/absent evidence, verified and unverified failures, account changes, logout, diagnostic redaction, retry countdown/clock adjustments, installation/login recovery during maximum generic backoff, rapid taps, rate limits, toggles, wake, timer collisions and reset follow-ups. Native fixture renders show missing/unsupported and waiting states without starting providers or writing production preferences.

Universal Release build, production privacy/source and bundle checks, Developer ID signing/strict verification, 17 packaging tests and 14 updater-policy tests passed. Physical Intel runtime and actual download/install/relaunch remain unverified for this correction. The signed review app is not notarized or published.

The installed public 1.1.2 executable still matches the preserved baseline hash. No installed app replacement, CLI configuration/authentication change, provider permission expansion, update installation, appcast promotion or public publication was performed.
