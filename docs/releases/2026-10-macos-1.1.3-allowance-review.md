# macOS 1.1.3 allowance review

Local review candidate, 5 October 2026. Bundle version/build remains **1.1.3 / 3**. This change extends normalization, allowance presentation and refresh state handling. Completed setup, installation, Settings controls, appearance, activity detection and dragging are preserved. Windows and per-project usage remain parked.

## Result

Usage and expanded monitor details list every supported time allowance, with scope, reported duration, explicit remaining percentage and supplied reset times. Compact selection is general five-hour, then general weekly, then deterministic shortest general duration. Model/additional time windows remain separate; credit/spend metadata never substitutes for a general percentage. Zero usage and exhausted usage are valid.

The owner's copy correction replaces the visible “General” scope label with “5-hour limit” or “Weekly limit”; unfamiliar reported durations have a duration-specific limit label. Model/additional prefixes remain distinct. Cards, expanded details and accessibility share these labels. This changes presentation only; normalization, selection and provider collection are unchanged. The focused presentation suite and isolated native fixture capture passed nine tests with zero failures.

Codex uses reported bucket metadata and durations rather than primary/secondary assumptions. Equivalent legacy/multi-bucket windows are merged; contradictory mirrors fail closed. Separator-safe identities prevent distinct buckets from losing rows. Claude preserves verified general and model time windows; opaque fields never receive invented consumer labels.

Missing, unsupported billing/format, retrieval failure and stale observations have distinct states. Empty success cannot appear Live. Stale readings require reverified matching binding and show observation age. Logout, changed/unverified bindings, incompatible envelopes and provider disablement clear old observations. Optional malformed fields are discarded without synthetic replacements; valid neighboring percentages survive.

One flight and one scheduled timer per provider bound work. Reset refreshes wait until after the supplied instant and respect a 30-second cadence; retries start at 30 seconds, or 60 for recognized rate limits, and cap at 15 minutes. Sleep/stop/disable cancel timers. Past resets never imply a refill. Command-1 opens equivalent complete details in Usage; cards and the monitor expose full accessibility labels.

## Compatibility boundaries

The [official Codex app-server contract](https://learn.chatgpt.com/docs/app-server) establishes the legacy and multi-bucket representations, duration fields and separate credit metadata. The [Claude authentication guide](https://code.claude.com/docs/en/authentication), [cost guide](https://code.claude.com/docs/en/costs) and [usage guidance](https://support.claude.com/en/articles/9797557-usage-limit-best-practices) distinguish subscription and other billing modes. Plan price/name does not determine returned windows.

Claude model-scoped weekly meaning was also verified against the installed official CLI 2.1.288 schema and formatter. That is implementation evidence, not a stable public API guarantee or proof every tier returns those allowances. No live non-null model allowance was established.

Codex's existing account response exposes type/email/plan, but no workspace identity. Binding checks cannot distinguish otherwise identical workspace contexts that the integration does not expose. Claude additionally binds organization. No new identity/credential extraction was added. Monetary balances, spend and reset-credit values remain undisplayed; “unsupported” describes Llumi's monitoring limitation. Rejected optional fields have no separate field-level invalidity badge.

The existing Codex client-info handshake still advertises 1.1.1; this pre-existing internal string was retained. App/Sparkle bundle version is 1.1.3/build 3. Intel is build-verified only. Fixtures and one Mac do not verify every subscription tier, billing mode or physical account transition.

## Focused adversarial review

Reviewed binding revalidation, late-result isolation, cache clearing, malformed/unknown fields, contradictory and colliding identities, diagnostic redaction and subprocess/timer exhaustion. Added regressions for findings. Existing no-inference/control-session guards, output/time/process limits and fixed diagnostic categories remain. No credentials, configuration, hooks, permissions, billing, reset-credit consumption or messages were added. No known implementation blocker remains; the physical and cross-plan limitations above remain explicit release validation work.

Stop before installation, upgrade or public release. Owner acceptance of this preview does not itself establish those distribution gates.
