# Llumi 2.2.0 for Windows — draft release candidate

Optional usage alerts, snooze controls and Start in background for the existing Codex and Claude Code providers.

## Usage alerts

- Usage alerts start **off**. Enable them in Settings, with default thresholds at **75, 90 and 95 percent used**.
- Edit each threshold to a distinct whole percentage from 1 through 100. Enable or disable thresholds and provider alerts independently.
- Warnings use eligible, fresh, verified readings for each supported quota window and include its reported reset time. Unknown, stale or unsupported readings do not produce automatic alerts.
- Handled thresholds remain remembered across restarts with intact local alert state. Windows notification controls and Do Not Disturb still apply; a submitted notification does not prove a banner was displayed.
- Send a test notification and check notification availability from Settings. Alerts warn about usage; they do not stop agents or impose spending limits.

## Alert snooze

- Snooze for one hour, snooze until tomorrow at 09:00 local time, or resume early. The saved deadline appears in Settings and survives restarts.
- Monitoring continues during snooze. The first fresh reading after snooze ends establishes a silent baseline, including after sleep, offline time or restart. Only higher thresholds reached in subsequent readings may notify, preventing a backlog.
- Test notifications bypass snooze without consuming usage thresholds.

## Start in background

- Start in background is initially **off** and controls ordinary cold launches. It is independent of Launch at Startup; login launches retain their quiet behaviour.
- First-time setup remains visible. Opening Llumi again restores the existing window, and changing this preference applies to future launches without hiding the current window.
- When the tray icon is disabled, background startup retains a minimized taskbar window. Closing continues monitoring; explicit Quit exits Llumi.

## Candidate scope and acceptance

The owner selected product version **2.2.0** and MSIX version **2.2.0.0** and confirmed that usage alerts, snooze and Start in background work in local use. This is permission to prepare a Windows release candidate, not to publish it.

The candidate covers these three Windows features. Existing provider authentication, collection and the desktop monitor remain in place. This update does not add providers, a taskbar strip, macOS changes or a direct-download release channel.

The local feature confirmation does not establish packaged installation or upgrade acceptance, provider sign-in acceptance in the candidate package, Windows login-startup acceptance, or Microsoft Store certification. Record those results separately when performed. This draft does not claim Store submission, publication or public availability.

The previous release history, public release feed and site configuration are preserved. Behaviour and validation requirements are defined in the [Windows alerts and background contract](../product-spec/windows-alerts-background.md).
