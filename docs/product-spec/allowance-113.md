# macOS 1.1.3 allowance correction

This approved change extends the existing normalization and state model. Version/build stays 1.1.3/3. Completed setup, Settings, installation, activity detection and monitor dragging remain intact. Windows and per-project usage remain parked; their earlier allowance presentation is not evidence of parity with this Mac correction.

Preserve valid reported time allowances with bucket identity, verified scope, duration, used percentage and optional reset. General, additional/model-specific time windows and credit/spend metadata are separate. Unknown fields are not assigned invented semantics. Percentage zero is valid. Malformed values are rejected, not clamped or replaced. Neither plan price nor plan name determines which windows exist.

Codex primary/secondary slots are transport identifiers, not duration semantics. Merge equivalent legacy and multi-bucket representations without duplicating allowances; reject ambiguous contradictory representations. Use duration and provider bucket metadata. Claude recognizes verified five-hour and weekly fields. The installed official Claude 2.1.288 control-response schema and formatter establish Sonnet/Opus weekly model windows and `model_scoped` as per-model weekly allowances with a server-supplied display label; these stay model-specific. This is provider implementation evidence, not proof that every account returns these fields or a stable public API guarantee. Other opaque unrecognized fields must not leak as consumer labels.

All supported reported time allowances appear in Usage and expanded details with scope/window labels, explicit remaining percentages and reset instants when supplied. Compact selection uses usable general windows only: five-hour, then weekly, then deterministic shortest reported duration. Model, additional non-general, spend and credit data never substitute. Equal card sizing remains. A keyboard or accessibility interaction must expose equivalent details without changing the nonactivating monitor's drag behavior.

Consumer labels use “5-hour limit” and “Weekly limit”; other reported durations use a duration-specific limit label. The internal general scope is not shown as “General” in Usage, hover or accessibility details. Model/additional labels retain their scope to distinguish separate limits. Missing duration is labeled “Usage limit · Period not reported”. Windows presentation remains parked.

Usage cards are informational, with no click-to-focus outline. Complete details remain available through Command-1 and accessibility labels. Light mode uses a pale card fill, clearer neutral border and subtle shadow to separate cards from the page. Dark-mode fill and border retain their previous appearance; equal sizing and allowance behavior are unchanged.

The Claude Usage card uses Anthropic's Claude Code pixel mascot, with the provider name beside it. Bundle the vendor artwork locally. Preserve the existing Codex mark, setup presentation and notch artwork.

Distinguish reported, not reported, unsupported format/billing, failed retrieval and stale observations internally and with concise UI state text. Empty and unknown-only successful responses never appear Live. Missing fields never imply unlimited or a synthetic zero/full allowance. Fresh successful missing responses invalidate old observations rather than reusing them as current data.

Retain stale data only after the same account binding is reverified. Failed continuity checks, account switches, logout and disablement clear previous-account data. Stale cards/details report observation age. Resets trigger a bounded refresh through the existing single-flight scheduler; past timestamps do not imply refills. A 30-second reset-refresh cooldown also bounds moving near-future timestamps. Rate limits and repeat failures impose backoff capped at 15 minutes and respected by automatic, activity and manual refresh requests; reset scheduling cannot bypass it. Cancellation, sleep/wake and provider disablement clean up scheduled work.

Credit, spend and extra-usage metadata is not converted into time percentages. Nonempty monetary metadata alone is an unsupported allowance format; its presence never establishes a billing mode. Known unsupported authentication/billing modes are classified from the existing auth evidence only. Empty/missing metadata stays not reported. Supported time windows continue to appear alongside unsupported monetary metadata.

Collection remains read-only through the existing integrations. No new credentials, permissions, configuration writes, hooks, inference, billing/reset-credit actions or messages. Diagnostics remain fixed categories with no raw payloads, identity/binding, account metadata or provider-controlled strings.

Validation separates regression fixtures from live accounts. Review both-window, single-window, no-data and stale fixtures in an isolated capture process/domain without live collectors or persistent production usage. Record current real-account evidence separately and leave untested plan/billing combinations explicit. Build and sign a local review app only; installation, upgrades and publication need later approval.
