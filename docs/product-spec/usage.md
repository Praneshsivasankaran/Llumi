# Usage

macOS 1.1.3 follows [the approved allowance requirements](allowance-113.md). Windows 2.1.3 adopts that allowance contract; [Windows catch-up requirements](windows-213.md) records its presentation, setup and intentional native differences. The rules below supersede the earlier longest-window, five-hour-only and weekly-secondary behavior.

macOS 1.1.3 shows only enabled providers in equal-width, equal-height cards aligned at headings, primary values and bars. Reserve whitespace for differing window counts rather than inventing data. Both providers off shows a Settings action. Remove the introductory allowance subtitle and signed-in-provider footer; retain observation age and refresh. Windows retains its native card layout described in the Windows requirements.

macOS navigation keeps Usage, Settings and About in the sidebar. Remove the default Show/Hide Sidebar toolbar button; retain the existing sidebar layout and navigation.

Llumi is one product with native platform implementations. Its primary destinations are Usage, Settings and About. Provider names are Codex and Claude Code. The official Llumi icon identifies the app. Windows uses its full-color icon in the notification area; macOS retains its native monochrome menu-bar variant.

Usage presents each provider's status, primary remaining percentage, slim progress, supported windows, reset information and observation details. Remaining means 100 minus verified used percentage. Unknown is a dash, never zero or full. Both providers select a usable general five-hour allowance first, then weekly, then the deterministic shortest supported general duration. Model-specific and additional allowances, including Spark, never substitute for a missing general allowance.

Full Usage retains every supported general, model and additional time window with its verified scope, duration, percentage and optional reset. Claude includes verified general five-hour and weekly windows, Sonnet and Opus weekly windows, and supported labeled model-scoped weekly windows. Codex preserves actual reported durations and separates general and additional buckets. If no usable general allowance exists, the primary value remains unknown while other supported detail rows remain visible.

Unknown or unsupported fields and identifiers must not appear as raw labels, tooltips or accessibility text in consumer Usage, compact or expanded/hover surfaces. Do not infer an unknown window's meaning from a name, prefix or duration, or promote monetary/credit metadata into time allowances. Use explicit normalized scope and supported-window rules rather than a denylist of observed identifiers. Windows uses concise model labels and Spark limit while retaining scope/duration in accessibility. Diagnostics remain category-based and do not export bucket identifiers. Native surface layouts and visible copy differ intentionally; allowance semantics remain shared.

Show Loading, Live, Stale, Not installed, Not signed in and Unavailable, keeping verified authentication separate from monitoring availability and unsupported format/billing. A refresh never erases the last observation or silently makes stale data live. Windows shows a quiet calendar observation label, with precise time/age and stale reasons available through accessibility and tooltips. Past resets await a new verified reading and never imply a refill. Full window detail remains available here when expanded-monitor work-area bounds require an overflow action.

The ordinary automatic refresh interval is 30 seconds; failure backoff and protected rate-limit embargo may defer it. Manual Refresh enters the same per-provider scheduler and respects its per-provider guards. One in-flight query per provider, coalesced repeated requests, bounded time/output, cancellation and complete owned-helper cleanup are required. A slow or failed provider cannot block the other.
