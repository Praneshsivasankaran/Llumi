# Release notes and update completion

The website adds a Release Notes navigation tab, a `/releases/` history and permanent platform/version pages such as `/releases/macos/1.1.3/`. Notes use reviewed release metadata and short descriptions of shipped behavior. Public releases and unreleased local previews remain visibly distinct. No preview download, invented publication date or publication claim is allowed. The 1.1.3 page is an unreleased preview until owner approval; public download configuration and the existing signed feed remain intact.

For review, an explicitly local-only build includes an interactive update-flow preview. It demonstrates automatic and manual installation paths, a successful new-version launch, a one-time completion popup and the exact version's patch notes. The completion copy is “The app has been updated” with the installed version, “View release notes” and “Continue.” A failed or canceled installation must not show the success popup; checking for an update or downloading it is not successful installation. First installation and ordinary relaunch must not claim an update. Review simulations neither install an app nor change real updater preferences. They are excluded from ordinary website builds.

Automatic checking and automatic installation are separate capabilities. The real application's opt-in must accurately state which capability it enables; completion follows successful installation and launch for either automatic or manual updates. The owner selected automatic download followed by a restart prompt: “Restart and update” or “Later.” No forced restart is permitted. Completion appears only after the new installed build launches. A version-specific completion record and exact trusted HTTPS release URL are needed for one-time acknowledgment, with first-install, cancellation, failure, downgrade and offline coverage.

Pinned Sparkle 2.10.0 review confirmed that current Llumi 1.1.2 and the local 1.1.3 preview disallow automatic installation. The 1.1.3 coordinator redirects scheduled checks to information-only probes. Enabling installation requires a separate native change; the website does not enable it. Sparkle ordinarily prepares automatic updates and installs at quit. Installation success must be established from the new running build, not a successful update-check callback. The old 1.1.2 binary controls its first upgrade and has no Llumi completion baseline; it cannot gain automatic installation retroactively. A review simulation is not proof of that physical upgrade or bootstrap acknowledgment.

This task prepares the website and local flow for review. Native updater integration, a Mac-only physical upgrade, website deployment, signed feed promotion and public binary release each retain their existing approval gates. Windows updater work remains parked. Email or push-message distribution is not part of this feature.
