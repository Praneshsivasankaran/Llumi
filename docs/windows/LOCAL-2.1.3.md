# Windows 2.1.3 local review

Local catch-up implementation based on the macOS 1.1.3 allowance/setup requirements. Reference behavior is taken from the released tag, not from the different platform version numbers. This supersedes the earlier Windows 2.0.3 restriction to general Claude windows.

## Changes

- Preserve supported general, model and additional time windows. Choose compact general five-hour, weekly, then shortest valid duration; additional/model limits cannot replace it. Details use duration/scope labels and preserve verified zero/exhausted values.
- Distinguish Not reported, Unsupported format, Unsupported billing, Unavailable and Stale, with current sign-in evidence separate from allowance readiness. Fresh empty responses clear old observations. Stale values require current proof of the same account; account/logout/verification failures clear previous data.
- Add shared per-provider switches in Settings/setup. Persist old preferences with both providers enabled by default; off stops queries/discovery/activity, cancels owned work, fences delayed results and removes cards/monitor entries. Both off has a Settings action.
- Add single-flight/manual ten-second minimum, exponential background backoff capped at fifteen minutes, reset refresh cooldown and a separate monotonic rate embargo that survives toggles/sleep/wake. Repeated rate-limit responses without a provider retry duration increase the protected wait from sixty seconds to fifteen minutes; manual Retry cannot bypass it. Preserve explicit provider waits and rate-limit evidence even when later account verification fails. Recognize documented Codex overload responses by error code. Retry can recheck during generic background backoff; checking/countdown indicates when it can actually run.
- Simplify welcome/setup copy, keep Windows copy-only PowerShell commands and authoritative startup handling. Show sign-in and monitoring separately.
- Center the official Llumi logo and name with a blue Get Started button underneath. Keep Welcome centered when resizing, preserve Enter and repeated forward/back navigation, and show navigation from the provider step onward.
- Keep the original spacious setup dimensions at the current display scale, fit the initial window inside the screen's work area, and preserve its size between steps. Fix footer overlap and clipped navigation/command buttons. Provider selection now shows only the two switches and navigation.
- Use the setup window's space consistently: center each page as a group, place navigation just below its content, and give provider choices, commands, checks and preferences padded full-width sections. Center the completion logo, confirmation and actions. Keep the concise wording and Light default. On smaller windows, scroll the whole page with all controls reachable; each new step starts at the top and status updates preserve the current scroll position.
- Default fresh profiles to Light across all setup steps, Usage, Settings and the monitor, regardless of Windows appearance. Match macOS by moving existing appearance preferences to Light exactly once, preserving every other setting and writing migration completion atomically with the appearance. A failed write leaves the stored preferences intact and allows a later retry. Later explicit Dark or System choices persist across restarts. Keep every setup page Light even when reopened from a Dark/System app, without changing the saved choice or recoloring Usage/the monitor. Preserve the existing serialized appearance identifiers.
- Simplify both provider guides to a short PowerShell cue, numbered Install/Sign in commands with Copy buttons and a small Setup help link. Remove prerequisite/skip/new-window paragraphs and the status/Retry/diagnostics/countdown cluster from these pages. Check Setup retains separate sign-in/monitoring checks, Retry, diagnostics and the shared switches, including both off and failed-save rollback. Show automatic failure-backoff timing separately from manual availability, and retained rate-limit waits after re-enabling without implying a check started.
- Complete the setup cleanup: remove passive Preferences copy and repeated checks from the final page; keep retry timing brief and avoid duplicate checking/off messages. Report rejected preference/startup changes in setup, restore the saved value without another write, and expose current button labels and status/stale details to accessibility.
- Keep unsupported responses distinct during setup. Preserve general allowances when case-distinct Codex buckets or malformed individual Claude model entries coexist, merge equivalent model entries, reject conflicting entries and recognize Claude Foundry as unsupported billing before requesting usage.
- Support Claude Code's telemetry opt-out in the isolated usage helper. Set `DISABLE_TELEMETRY=1` only for Llumi-owned Claude child processes, retain inherited privacy options, and require the provider's telemetry-disabled authentication evidence. Do not edit CLI settings, enable telemetry or send inference requests; before/after account verification and subprocess isolation remain enforced.
- When expanded monitor details exceed the screen, show complete rows, preserve status and show the number of remaining allowances with Open Usage. The full list is available through the existing click and keyboard actions.
- Cancel pending hover work throughout a monitor press/drag. Scale the movement threshold with display DPI and remember a drag once the threshold is crossed. Preserve a normalized display anchor through expansion, collapse, work-area changes and scaling, while reading existing saved positions compatibly. Expanded details show provider names and observation age, including stale readings.
- Equal Usage card sizing, consistent official Codex blossom/Claude Code pixel artwork, all supported expanded allowance details, stale age/accessibility text, keyboard access to Usage, and Reset Position in Settings/monitor menu.
- Remove the Settings tray-availability explanation, independence/account/telemetry note and automatic-save footer; preserve error messages and collapse the unused message area.
- Remove the Setup Llumi button from Settings and close its reserved gap. First-time onboarding, existing menu access, and the separate review tool remain available.
- Remove the passive diagnostics privacy note and its empty layout space. Copy Diagnostics retains concise success/clipboard-error feedback after use.
- Simplify named additional/model rows to Spark limit, Opus and Sonnet; retain scope/period in accessibility metadata. Match the dashboard identity to the official Llumi application icon.
- Match the Windows tray icon to the same official full-color Llumi tile, using the embedded small sizes instead of a separately drawn monochrome gauge. Preserve display-change reload, tray interactions and status tooltips.
- Correct packaged artwork notices to identify the OpenAI blossom, Claude Code pixel mascot and original Llumi Raspberry gauge. Record the bundled vendor assets' actual sources and source hashes in [artwork provenance](PROVIDER-ARTWORK.md); setup artwork follows its local Light surface even when the application uses Dark.
- Add About to the native application navigation/menu, with the official Llumi icon, installed version, bundled offline release notes and Open Microsoft Store. Keep Store-managed download, signing and installation; do not claim a completed update without verified installation evidence.
- Add draft Windows 2.1.3 release metadata shared by the bundled notes and a separate local website preview. The preview uses the macOS release-page style, explicitly says unreleased, and has no publication date or download. Keep public website configuration/history, the default site builder and release feeds unchanged.
- Add a development-only live first-time review mode with fresh isolated settings, complete native setup, real provider checks and sandboxed startup. Preserve the installed Store app and existing CLI credentials.
- Set the owner-review version to 2.1.3 (Windows file/assembly version 2.1.3.0) and show it in the first-time review window title. Microsoft Store remains the Windows update channel; submission awaits explicit owner approval. No Sparkle, installer, public release, production website change or Store metadata change. Rejected setup GIFs and removed instructional paragraphs remain absent.

## Local review

Build the production app with `pwsh -NoProfile -File windows/tools/build.ps1`. The framework-dependent output is `windows/artifacts/release/Llumi.exe`; it needs the .NET 10 Desktop Runtime. The script creates local files only.

An additional development-only `AgentMeter.ReviewHost` project reuses the native application forms. Its default scenario toolbar uses fixed synthetic examples, no collectors/activity scanners, memory-only preferences/startup and no product single-instance locks. Use it to inspect both-window/model, weekly-only, missing/unsupported, stale, provider-off and themes. Capture output includes every setup step; these are fixture renders, not real-account or physical acceptance.

The separate `--first-run-live` mode starts the full native application with an empty isolated profile and real provider checks. It preserves the installed Store app, existing settings and CLI sign-ins, skips importing installed/legacy preferences and acquires the normal product/legacy locks. Quit another Llumi instance normally before opening it. Startup toggling stays inside the review profile; it does not register this development helper with Windows. The delivery includes a launcher that creates a fresh profile for each first-time run. Neither review mode is included in production packaging.

Build the separate offline website preview with `python scripts/build-windows-release-preview.py --output <local-review-directory>`, then open `releases/windows/2.1.3/index.html` inside that directory. It also contains a local archive and schema-compatible `releases-preview.json` for later review. This command does not run the public website build or modify release history, download configuration or update feeds. Do not deploy its output.
